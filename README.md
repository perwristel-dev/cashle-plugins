# Cashle source plugins

Each directory under `plugins/` owns one source package and its catalog metadata. `npm run build` writes `dist/plugins/index.json` and the verified ZIPs with no compiler or third-party Node dependencies. Use `node build-catalog.mjs --release <directory>` to record a local release after editing a package.

Keep `catalog.json`'s `name` as the canonical name. Add `names.en` and `names.sv` for the display names in Cashle. These fields appear in the catalog index, so editing a display name leaves the ZIP and package version unchanged.

The GitHub Actions workflow builds and publishes `/plugins/` when catalog
inputs change on `main` or when started manually. Configure the repository's
Pages source to **GitHub Actions**. The workflow keeps published versions for
unchanged archives and assigns a new version to changed archives.

In Cashle, configure the published directory URL as `CASHLE_PLUGIN_CATALOG_URL`. Other catalogs can use the same directory layout and be added by URL from the Plugins page.

## Run DSL calculation tests

Install Node.js 22 or newer and JDK 17. The tests use Node's built-in test
runner and a Maven ZIP containing Cashle's local calculation runtime.

```sh
npm run test:prepare
npm test
```

Preparation checks the runner's published checksum at
`https://cashle-lab.com/maven/` and downloads the ZIP when that checksum is
new. It uses Cashle's catalog installer to resolve dependencies from the core
and source plugin catalogs. Keep `.cashle-tests/` between runs. Each lock
records the runner used to prepare it and the cached plugin ZIPs, so the
test command runs offline. Run preparation again when you change dependencies
or want to refresh their versions. The DSL test workflow is available on
manual dispatch in GitHub Actions.

Put the authored scenario and its assertions in your plugin's `test/`
directory. Add a `test/dependencies.json` with any extra `plugins` and
`catalogs` arrays. Preparation also follows the tested package's own
dependency declarations. Each plugin gets a lock in `.cashle-tests/`
and shares the ZIP cache. The [ISK test](plugins/swedish-isk/test/topup.test.mjs) builds a
ZIP from the current checkout and uses it instead of the cached ISK ZIP.
It asserts the account balance and posting generated by the local JVM.

To test a runner before publication, pass its Maven ZIP path in
`CASHLE_DSL_RUNNER_ZIP`. Preparation uses that ZIP instead of fetching the
published runner. Use
`CASHLE_TEST_CATALOG_DIRS` for local catalog snapshots, with paths separated
by the platform's path separator.
